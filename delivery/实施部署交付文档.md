# SuperAGI 0.0.14 × GaussDB 507 实施部署交付文档

> 适用版本：SuperAGI 0.0.14 / GaussDB 507.0.0+（集中式，A 兼容模式）

## 2. GaussDB 环境前置条件（管理面操作）

### 2.1 内核版本与向量开关

- 内核版本要求 **507.0.0 及以上**。
- 向量能力开关 `enable_vectordb` 必须为 on。核对方式（gsql 中执行）：

  ```sql
  SHOW enable_vectordb;
  ```

  若为 off，执行以下命令后**重启实例生效**：

  ```bash
  gs_guc set -c "enable_vectordb=on"
  ```

### 2.2 建库与建用户

```sql
CREATE DATABASE super_agi_main DBCOMPATIBILITY='A' ENCODING='UTF8';
CREATE USER superagi WITH PASSWORD '你的密码';
ALTER DATABASE super_agi_main OWNER TO superagi;
```

- 库兼容模式必须为 **A**（t1_connect.py 会校验）。
- 编码必须为 UTF8。

### 2.3 权限（必做）

GaussDB 507 收紧了 public schema 的默认权限，**即使库 owner 也需要显式授权**，否则迁移建表失败：

```sql
GRANT CREATE, USAGE ON SCHEMA public TO superagi;
```

### 2.4 认证方式

- 开源 **psycopg2 2.9.x 直连**，md5 认证实例验证通过。
- sha256-only 认证的实例无法用开源 psycopg2 直连，需将 `password_encryption_type` 设为 1、gs_hba 中对应网段配置 md5、并重置用户密码（重置后新密码以 md5 存储），参考 dify 适配经验。

### 2.5 向量维度限制

- **集中式**：向量维度上限 4096；维度 >1024 时自动选用 GsDiskANN + PQ 索引。
- **分布式形态**：建表硬限 **1024 维**，超维建表直接报错 `dimensions for type vector cannot exceed 1024`。使用 ada-002（1536 维）等超维模型的场景不可用分布式形态。

## 3. SuperAGI 部署步骤

### 3.1 配置 config.yaml

两种方式（**推荐分项配置**，密码无需编码）：

方式一（推荐）——分项配置，按 `.env.gaussdb.example`：

```yaml
DB_HOST: 127.0.0.1
DB_PORT: 5432
DB_USERNAME: superagi
DB_PASSWORD: 你的密码
DB_NAME: super_agi_main
```

方式二——完整 URL：

```yaml
DB_URL: opengauss+psycopg2://superagi:你的密码@127.0.0.1:5432/super_agi_main
```

注意：

- DB_URL 的 scheme **必须是 `opengauss+psycopg2`**（不是 `postgresql+psycopg2`）。
- 密码含 `@ : /` 等特殊字符时，DB_URL 中的密码必须 percent-encode（如 `@` → `%40`）；分项配置无需编码。
- 两种方式都支持，分项方式内部同样由连接 helper 构建正确 URL。

### 3.2 安装依赖

`requirements.txt` 已包含 `opengauss-sqlalchemy==2.4.0`，直接按原有流程安装即可，无需手工加包。

### 3.3 启动与迁移

`entrypoint.sh` 自带 `alembic upgrade head`，首次启动自动建表。启动后验证迁移终态：

```bash
alembic current        # 期望输出 9270eb5a8475 (head)
```

数据库侧核对：

```sql
SELECT version_num FROM alembic_version;                    -- 9270eb5a8475
SELECT COUNT(*) FROM pg_tables WHERE schemaname='public';  -- 39 张表
```

分层测试 t2_migrations.py 对此做了断言（head=9270eb5a8475、表数下限、events.event_property 为 jsonb），可直接复用。

### 3.4 Redis

- Redis **仍为必需组件**：Celery 的 broker / backend / 任务队列依赖它。
- 不再需要 redis-stack 的 **RediSearch 模块**（向量已走 GaussDB），普通 Redis 即可。原 `RESOURCE_VECTOR_STORE=REDIS` + RediSearch 的向量路径不再使用。

## 4. 向量存储说明

### 4.1 开启方式

```yaml
RESOURCE_VECTOR_STORE: GAUSSDB
LTM_DB: GAUSSDB
```

- 向量表默认建在**元数据库同实例**（同库）。
- 如需独立向量库实例，可用 `GAUSSDB_VECTOR_DB_URL` 覆盖为独立连接（`opengauss+psycopg2://...`）。

### 4.2 默认 index 名

默认 index 名 `super-agent-index` / `super-agent-index1`（含连字符）已支持——GaussDB 向量表名允许连字符，适配已处理（提交 `c80a918`）。

### 4.3 索引类型自动选择

按向量维度自动选择索引类型，无需人工干预：

| 维度 | 索引类型 | 参数 |
|---|---|---|
| ≤1024 | GsIVFFLAT | IVF_NLIST=256 |
| >1024（如 ada-002 的 1536） | GsDiskANN + PQ | pq_nseg 自动按维度整除计算 |

### 4.4 惰性建表与建索引

- 向量表与索引均为**惰性创建**：首次写入数据时触发，无需提前手工建表。
- 建索引前自动 `SET maintenance_work_mem='512MB'`，加速索引构建。

## 5. 回滚

### 5.1 应用侧

- 逐个 `git revert` 适配提交序列；保底方案是回退到 `2f84bfa` 基线（适配前状态）。
- 最小回滚：`config.yaml` 中把连接换回 `postgresql://`（PG 形态），即可回原 PostgreSQL 部署，代码兼容 PG（opengauss 方言仅在 GaussDB 连接时使用）。

### 5.2 数据库侧

- 34 个迁移全部支持完整 downgrade。上游 5 个迁移原本 downgrade 损坏（列名参数错误、rename 不对称、缺失 drop），已在本适配中修复（提交 `585827e`），并通过 **34 + 34（upgrade 全量 + downgrade 全量）双向回归验证**。
- 回滚数据库即执行 `alembic downgrade base` 后按需 DROP 库。
