# 测试指南

> 适用对象：SuperAGI 0.0.14 × GaussDB 507 适配的交付验证。
> 测试环境统一使用虚拟环境 `.venv-gauss`（Windows 路径 `.venv-gauss\Scripts\python.exe`）。

## 1. 单元测试（不连库）

覆盖连接 helper 与 GaussDB 向量后端的纯逻辑（URL 构建、索引参数计算、字面量生成等），共 **21 个用例**（连接 helper 10 + 向量后端 11），不依赖 GaussDB 实例，可在任意机器执行：

```powershell
.venv-gauss\Scripts\python.exe -m pytest tests/unit_tests/test_gaussdb_db_connection_helper.py tests/unit_tests/test_gaussdb_vector_store.py -v
```

期望：21 passed。

## 2. 分层真库测试（delivery/tests）

依次执行以下脚本，环境统一为 `.venv-gauss`。每个脚本头部注释均写明用法；`t3` / `t4` 自带数据清理，可重复执行。

```powershell
cd delivery\tests
..\.venv-gauss\Scripts\python.exe reset_test_db.py
..\.venv-gauss\Scripts\python.exe t1_connect.py
..\.venv-gauss\Scripts\python.exe t2_migrations.py
..\.venv-gauss\Scripts\python.exe t3_crud_empty_string.py
..\.venv-gauss\Scripts\python.exe t4_vector.py
```

### 0. reset_test_db.py

重置测试库 `super_agi_test`：DROP 全部表后重跑 `alembic upgrade head`（重放全部 34 个迁移）。

> **警告：会清空 `super_agi_test` 库全部数据，仅允许对测试库执行**，严禁指向生产库。

### 1. t1_connect.py —— 连通 / 方言 / 兼容模式

验证 opengauss+psycopg2 连接可建立、方言为 `opengauss`、库兼容模式为 `A`。任何后续步骤失败时先跑本脚本定位连接问题。

### 2. t2_migrations.py —— 迁移终态

断言三项：

- `alembic_version` = `9270eb5a8475`（head）
- public schema 表数 ≥ 38（实际 39 张）
- `events.event_property` 列类型为 `jsonb`

### 3. t3_crud_empty_string.py —— ORM CRUD + 空串拦截

验证 ORM 层增删改查正常、A 兼容模式下空串拦截生效（应用写入 `''` 被拦截改写为单空格 `' '`，规避 GaussDB 空串转 NULL 语义）、JSONB 列读写正常。脚本自带清理，可重复跑。

### 4. t4_vector.py —— 向量后端全链路

mock 1536 维 embedding，走 GsDiskANN+PQ 路径，覆盖：

- JSONB metadata dict 化（psycopg2 typecaster）
- upsert 原地更新（`ON DUPLICATE KEY UPDATE` 路径）
- 科学计数法向量字面量写入
- 相似度检索、metadata 过滤、按 id 删除

脚本自带清理，可重复跑。

## 3. 环境变量注意（跑分层测试时）

- t1–t4 与 reset 脚本内**已内置**测试库连接与密钥（`superagi_test` / `GaussTest2026`），无需外部配置即可运行。
- 原理提示：SuperAGI 的 config 在 **import 时快照环境变量**构造配置单例——任何自定义脚本如果要在 SuperAGI 连接自定义库，必须在 `import superagi` **之前**设置 `os.environ["DB_URL"]`（及 `ENCRYPTION_KEY`，32 字符），import 之后再设不生效。t3/t4 源码头部注释即为此示例。

### t7 结果（2026-09-21，共三轮：首验 + 修正复跑 + 最终轮，最终轮 `delivery/tests/_t7_run.log`）

最终轮汇总：**PASS=76 / FAIL=5 / BLOCKED=0**。5 个 FAIL = 4 个上游产品缺陷（与 GaussDB 无关，详见《注意事项》第 7 节）+ 1 个环境项：

1. `GET /models_controller/get_api_keys` 500（Local LLM 明文 "EMPTY" 被解密）——上游缺陷；
2. `GET /knowledges/user/get/details/{无效id}` 500（缺 None 守卫）——上游缺陷；
3. `GET /vector_dbs/db/details/{无效id}` 500（缺 None 守卫）——上游缺陷;
4. webhook 无 DELETE 端点且 `WebHookManager` 不过滤 `is_deleted`——上游缺陷；
5. `.md` 上传后的 summarize 向量落库在 900s 轮询内未完成——环境项：celery worker（solo）队列状态异常（redis 残留孤儿 unacked 消息）导致消费延迟；功能本身已证明：三轮中 resource 4/5 两次 `.md` summarize 均成功落库各 22 块（与 MarkdownReader 解析数一致）。

GaussDB 数据层本轮未发现新的兼容问题（JSON/JSONB 写读、JSONB `::int` 聚合、`array_agg(JSONB)`、向量落库与检索、空串守卫均通过）。
